# گزارش پیاده‌سازی فازهای ۸ و ۹

## معماری

ماژول‌های `notifications`، `files`، `audit`، `dashboard`، `workflow` و `performance` همگی جریان UI → Hook → Service → Repository → Data را رعایت می‌کنند. پیاده‌سازی فعلی مخزن‌های حافظه‌ای دارد و قراردادها برای جایگزینی با API یا پایگاه داده مستقل هستند.

زیرساخت مشترک `src/core` خطاهای ساختاریافته، ثبت لاگ با حذف داده حساس، اعتبارسنجی، مجوزها، پاک‌سازی ورودی و ابزارهای تاریخ/فرمت/شناسه/async را فراهم می‌کند. Audit تاریخچه تجاری است و Logger صرفاً رخداد فنی را نگه می‌دارد.

## امنیت و مجوزها

| نقش | داشبورد | گردش‌کار | ارزیابی |
| --- | --- | --- | --- |
| مدیرعامل | خلاصه سازمان و مقایسه واحدها | مشاهده سازمان و تأیید ارجاعات بدون دور زدن واحد | فقط خلاصه سازمان؛ بدون نظر خصوصی فردی |
| مدیر واحد | فقط واحدهای خود | مدیریت واحد، ایجاد وظیفه و بررسی | ایجاد/ویرایش/نهایی‌سازی کارکنان واحد خود |
| کارمند | فقط داده شخصی | فقط اقدامات واگذارشده؛ بدون تأیید کار خود | فقط ارزیابی نهایی و بازخورد خود |
| دبیر | جلسات و مستندات | فقط گردش‌کار جلسه | بدون دسترسی |

اعلان فقط توسط مالک خوانده/حذف می‌شود. فایل از مجوز موجودیت والد استفاده می‌کند. Audit فاقد update/delete عمومی، تغییرناپذیر و دارای حذف خودکار password/token/secret است. شکست Audit عملیات اصلی کسب‌وکار را rollback نمی‌کند و در Logger ثبت می‌شود.

## گردش‌کار و ارزیابی

- ماشین‌های وضعیت Task، Report، Request و Meeting گذار نامعتبر را رد می‌کنند.
- هر تغییر وضعیت، history و audit می‌سازد و در صورت نیاز اعلان می‌فرستد.
- رد تأیید نیازمند دلیل است؛ ارجاع مسئولیت را خودکار تغییر نمی‌دهد.
- Reminder فقط کاربران مرتبط را مطلع می‌کند.
- وزن معیارهای ارزیابی باید دقیقاً ۱۰۰ و امتیاز هر معیار بین ۰ تا ۱۰۰ باشد.
- تحلیل عملکرد فقط از منبع خواندنی وظیفه/گزارش/گردش‌کار محاسبه می‌شود.

## کیفیت و آمادگی تولید

- بارگذاری تنبل صفحه نمای کلی و fallback مبتنی بر Suspense
- cache با TTL و invalidation، کنترل درخواست تکراری، جست‌وجو/مرتب‌سازی سرویس‌محور
- pagination و DataTable واکنش‌گرا
- stateهای loading/empty/error، برچسب‌های قابل فهم و عناصر semantic
- Error Boundary سراسری و پیام فارسی بدون نمایش جزئیات فنی

فرمان‌های اعتبارسنجی:

```bash
npm run build
npm run lint
npm run verify:security
npm run verify:workflows
npm run verify:phase9
```

پیش از تولید واقعی باید adapterهای API/storage، provider پیامک، مانیتورینگ بیرونی، سیاست نگهداری log و تست مرورگر انتها-به-انتها به محیط اجرایی سازمان متصل شوند.
